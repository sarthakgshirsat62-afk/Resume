# Tech Stack

All libraries and tools used in this project, with rationale. No new dependency should be added without updating this file and confirming with the project owner.

---

## Framework

### Next.js 15 (App Router)
- **Why:** Full-stack React with SSR, SSG, ISR, and API routes in one framework. App Router enables React Server Components for zero-JS page sections, which is ideal for resume/portfolio content. Native streaming, layouts, and nested routing.
- **Pattern used:** App Router (`src/app/`) — no Pages Router.
- **Key features used:** Server Components, Server Actions, Route Handlers, Metadata API, Image Optimization.

---

## Language

### TypeScript (strict)
- **Config:** `strict: true`, `exactOptionalPropertyTypes: true`, `noUncheckedIndexedAccess: true`
- **Rule:** No `any`. Use `unknown` + type guards when type is genuinely unknown. Zod for runtime validation.
- **All files:** `.tsx` for components, `.ts` for everything else. No `.js`.

---

## Styling

### Tailwind CSS v4
- **Why:** Utility-first CSS with v4's native CSS variable support and Vite plugin. Eliminates CSS-in-JS overhead.
- **Pattern:** Design tokens defined as CSS variables in `src/styles/tokens.css`. Tailwind classes consume those tokens via `@theme`.
- **No:** Inline `style` props for theming. Use CSS variables through Tailwind classes.

### CSS Variables (design tokens)
- Defined in `src/styles/tokens.css`
- Covers: colors, spacing scale, typography scale, border radius, shadows, z-index
- See `/docs/theming.md` for the full token system.

## UI Components

### shadcn/ui
- **Why:** Unstyled, accessible Radix UI primitives with Tailwind wiring. Components are copied into the repo (not imported from npm) — full ownership and customization.
- **Location:** `src/components/ui/` (generated by shadcn CLI)
- **Rule:** Never modify generated `ui/` files directly. Wrap them in `common/` or `resume/` components instead.
- **Docs:** https://ui.shadcn.com

### Radix UI (via shadcn)
- Underlying accessible primitives: dialogs, dropdowns, tooltips, popovers, etc.
- Used indirectly through shadcn components.

### Phosphor Icons
- **Package:** `@phosphor-icons/react`
- **Why:** Consistent, large icon set with multiple weights. Works in PDF renderer via separate package.
- **Usage:** `import { ArrowRight } from "@phosphor-icons/react"` — always import named, never import the whole library.

## State Management

### TanStack Query v5 (server state)
- **Why:** Handles all async data fetching, caching, invalidation, and background refetching. Removes the need for manual loading/error state management.
- **Pattern:** Custom hooks wrap `useQuery`/`useMutation`. No direct `fetch` calls in components.
- **Keys:** Defined in `src/lib/query-keys.ts` as constants.

### Zustand (client state)
- **Why:** Minimal, non-boilerplate store for UI state (editor panel state, active section, theme selection, modal visibility). Not used for server data.
- **Pattern:** One store per feature domain. Files in `src/store/`.
- **Rule:** Don't persist server-sourced data in Zustand. That belongs in TanStack Query cache.

### React Hook Form + Zod
- **Why:** Performant forms with schema-driven validation. Zod schemas in `src/schemas/` are reused for both validation and TypeScript inference.
- **Pattern:** `useForm` + `zodResolver` from `@hookform/resolvers/zod`.

## Data & Backend

### PostgreSQL
- **Why:** Reliable relational DB. JSON columns for flexible resume section data.
- **Hosted on:** Railway (dev) / Supabase (prod option)

### Drizzle ORM
- **Why:** TypeScript-first ORM with full type inference from schema. Lightweight, no code generation step for queries.
- **Pattern:** Schema defined in `src/db/schema.ts`. Migrations in `src/db/migrations/`.
- **CLI:** `drizzle-kit` for migrations.

## Authentication

### Better Auth
- **Why:** Modern auth library with first-class TypeScript support, passkeys, OAuth providers, 2FA, and API key auth. Self-hostable.
- **Providers configured:** Email/password, Google OAuth, GitHub OAuth
- **Passkeys:** Enabled for passwordless login
- **See:** `/docs/auth.md` for full auth flow.

---

## PDF Export

### @react-pdf/renderer
- **Why:** Renders React component trees to PDF. Client-side generation — no server-side print service needed.
- **Pattern:** Separate PDF-specific components in `src/components/pdf/`. These use a restricted subset of React with PDF-compatible primitives.
- **See:** `/docs/pdf-export.md` for full pipeline.

---

## Email

### React Email
- **Why:** Write email templates as React components. Consistent with the rest of the stack.
- **Transport:** Nodemailer (SMTP)
- **Fallback:** Console logging in development (no SMTP required locally)
- **Templates:** `src/emails/`

## Code Quality

### Biome
- **Why:** Single tool for linting + formatting. Faster than ESLint + Prettier combined. Opinionated defaults.
- **Config:** `biome.json` at project root.
- **Rules enforced:** No explicit `any`, exhaustive deps, type-only imports, sorted imports, sorted Tailwind classes.
- **Run:** `biome check --write .` to format+fix.

### Vitest + Testing Library
- **Unit tests:** `vitest` — colocated in `__tests__/` folders or `*.test.ts` files.
- **Component tests:** `@testing-library/react` for behavior-driven UI tests.
- **Pattern:** Test behavior, not implementation. No snapshot tests.
