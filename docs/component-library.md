# Component Library

Component categories, composition patterns, rules, and anti-patterns.

---

## Component Layers

Components are organized into four layers with strict rules about what each layer can depend on:

```
ui/          ← Primitives (shadcn/Radix). No project-specific logic.
  ↓
common/      ← Site-wide layout/navigation. Can use ui/. No feature logic.
  ↓
resume/      ← Resume rendering. Can use ui/ and common/.
editor/      ← Editor UI. Can use ui/, common/, and resume/ for preview.
pdf/         ← PDF-only. Can NOT import from other layers (react-pdf constraints).
```

---

## `src/components/ui/` — Primitives

Generated by shadcn CLI. **Never modify these files directly.**

If you need a variant or customization:
1. Wrap the primitive in a new component in `common/` or the relevant feature folder
2. Pass `className` to extend styles
3. Never patch `ui/button.tsx` etc.

**Available primitives (add as installed):**
- `button`, `input`, `textarea`, `select`, `checkbox`, `radio-group`
- `dialog`, `sheet`, `popover`, `tooltip`, `dropdown-menu`
- `card`, `badge`, `separator`, `avatar`
- `label`, `form` (React Hook Form integration)
- `skeleton`, `scroll-area`, `tabs`

## `src/components/pdf/` — PDF Export

PDF components use `@react-pdf/renderer` primitives (`View`, `Text`, `Document`, etc.) — **not** standard HTML/CSS.

- Cannot use `className` or Tailwind — use `style={{ }}` with react-pdf style objects
- Cannot import from other component layers (react-pdf has its own render pipeline)
- Mirror the structure of `resume/` but with PDF-compatible primitives
- Kept separate because PDF styles and HTML styles are fundamentally different

## Component Composition Rules

### DO
```tsx
// Compose via children and props
<Card>
  <CardHeader>
    <CardTitle>Experience</CardTitle>
  </CardHeader>
  <CardContent>
    <ExperienceEntry entry={entry} />
  </CardContent>
</Card>

// Extract when used in 3+ places
const SectionHeader = ({ title }: { title: string }) => (
  <h2 className="text-2xl font-semibold text-foreground">{title}</h2>
);
```

### DON'T
```tsx
// Don't combine data fetching + rendering in one component
const ExperienceSection = () => {
  const data = await fetch("/api/experience"); // ← put this in a Server Component parent
  return <ExperienceList data={data} />;
};

// Don't build monolith components
const ResumeEditor = () => {
  // 500+ lines mixing form, preview, and sidebar logic
};

// Don't hardcode colors
<div style={{ color: "#1a1a1a" }}>   // ← use className="text-foreground"
```

## `"use client"` Boundary Rules

By default, all components are Server Components. Add `"use client"` **only** when the component:
- Uses `useState`, `useReducer`, `useEffect`
- Has event handlers (`onClick`, `onChange`, `onSubmit`)
- Uses browser-only APIs (`window`, `localStorage`, `IntersectionObserver`)
- Uses client-side libraries (Zustand, TanStack Query, react-pdf)

**Keep `"use client"` boundaries as deep as possible** — hoist server-rendered content up, push interactivity down into leaf components.

## Variant Patterns

Use `class-variance-authority` (CVA) for components with multiple visual variants:

```tsx
import { cva, type VariantProps } from "class-variance-authority";
import { cn } from "@/utils/cn";

const badgeVariants = cva(
  "inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-semibold",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground",
        secondary: "bg-secondary text-secondary-foreground",
        destructive: "bg-destructive text-destructive-foreground",
        outline: "border border-border",
      },
    },
    defaultVariants: { variant: "default" },
  }
);

interface BadgeProps extends VariantProps<typeof badgeVariants> {
  className?: string;
  children: React.ReactNode;
}

export const Badge = ({ variant, className, children }: BadgeProps) => (
  <div className={cn(badgeVariants({ variant }), className)}>{children}</div>
);
```

## Anti-Patterns

| Anti-pattern | Instead |
|---|---|
| Prop-drilling 3+ levels | Colocate or use context/store |
| Component > 300 lines | Split into sub-components |
| Inline styles for anything design-system related | Use Tailwind + tokens |
| `any` in component props | Define proper types from Zod schemas |
| Fetching data in a deeply nested component | Fetch in the page/layout Server Component |
| Mutating Zustand store from a Server Component | Mutations only from Client Components or Server Actions |
| Importing from `pdf/` in non-pdf components | Keep PDF layer isolated |
